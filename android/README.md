# 갤럭시 초기화 Android 앱

`V6.py`의 19단계를 Android 네이티브 앱으로 옮긴 프로젝트입니다. Windows EXE를 변환하는 것이 아니라 같은 DEX 헬퍼와 명령을 Shizuku shell(uid 2000)에서 실행합니다. 앱 ID는 `com.forholiday.galaxyreset`, 최소 Android 11입니다.

## APK 빌드

Android Studio에서 이 `android` 폴더를 열고 SDK 36과 Java 17을 사용합니다. SDK 경로는 Android Studio가 만드는 `local.properties` 또는 `ANDROID_HOME`으로 지정합니다.

```sh
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug
```

설치용 APK: `app/build/outputs/apk/debug/app-debug.apk`. 서명된 테스트 APK이며 실제 기기에 설치할 수 있습니다. Android Studio의 Build > Generate Signed App Bundle / APK로 운영용 APK를 만들고 서명 키를 보관하세요. 같은 기기에 업데이트할 때는 기존 설치와 같은 서명 키가 필요합니다. CI의 임시 debug 키는 실행마다 달라질 수 있으므로 운영 업데이트에 사용하지 마세요.

루트 폴더의 DEX 6개·PNG 4개·필수 앱 APK 2개는 빌드 시 자동으로 assets에 복사됩니다. 바이너리를 중복 관리하지 않습니다. Git으로 받은 경우 `git lfs pull`로 실제 APK 파일을 받아야 합니다. 전체 앱에는 약 100MB의 필수 앱 자산이 포함됩니다.

GitHub Actions의 **Build Android APK**를 수동 실행해도 APK를 받을 수 있습니다. 새 워크플로 파일은 저장소에 push한 후 실행할 수 있습니다.

## 폰에서 사용

1. Android 11 이상 갤럭시 소유자 프로필(사용자 0)에 이 APK와 [Shizuku](https://shizuku.rikka.app/download/)를 설치합니다.
2. Wi-Fi 연결 → 개발자 옵션 → 무선 디버깅을 켭니다. 개발자 옵션이 없으면 휴대전화 정보 → 소프트웨어 정보 → 빌드번호를 여러 번 눌러 활성화합니다.
3. Shizuku에서 무선 디버깅 **페어링**을 진행합니다. Android가 표시하는 페어링 코드를 직접 입력합니다. 이어서 Shizuku **시작**을 누릅니다.
4. 초기화 앱의 **Shizuku 연결·권한 확인**을 누르고 권한을 허용합니다. 기존 권한이 있으면 앱이 자동으로 연결합니다.
5. 언어를 선택하고 **초기화 시작 → 모두 지우기**를 누릅니다.
6. 완료 또는 일부 실패 화면에서 결과를 확인합니다. 계정/e-SIM/접근 제한 파일은 수동 확인이 필요할 수 있습니다. 실패 단계만 재시도하거나 연결 중단 단계부터 계속 실행할 수 있습니다.
7. 배경화면·기본 홈 화면을 실제로 확인한 뒤 **전원 끄기**로 출고합니다. 재부팅하면 기존 Shizuku 프로세스는 종료됩니다. 13.6 이상은 Android 13 이상에서 설정 권한·이전 ADB 시작 이력·신뢰하는 Wi-Fi와 페어링 정보가 유지되면 자동 시작을 시도할 수 있습니다. 자동 시작이 되지 않으면 Shizuku에서 다시 시작하세요.

초기 무선 페어링·Wi-Fi 신뢰 승인·초기화 앱의 Shizuku 권한 허용은 기기에서 처리합니다. 아래 PC 준비 기능으로 설치·설정·USB 기동까지 처리할 수 있으며, 최초 승인 후 초기화 실행은 폰 단독으로 가능합니다.

## 기존 Windows EXE에서 폰 단독 사용 준비

`V6.py`의 18단계에서 네이버 지도·파일 관리자와 함께 **갤럭시 초기화 앱과 공식 Shizuku 13.6.0**을 설치합니다. 기존 초기화 앱과 Shizuku는 사용자 앱 삭제 대상에서 제외합니다. 같은 버전이나 최신 버전은 유지하고, 구버전은 `adb install -r`로 업데이트합니다. 서명 충돌이 발생하면 삭제 후 재설치하지 않고 실패로 표시합니다.

PC는 개발자 옵션·USB/무선 디버깅을 켜고, 필요한 설정·알림 권한을 부여하며, 두 앱을 배터리 제한에서 제외하고 Shizuku 서버를 USB로 시작합니다. 필수 앱 설치·설정·서버 시작을 확인하지 못하면 해당 기기의 작업을 실패로 표시합니다. 배터리 제한 제외 실패는 별도 안내로 남깁니다. 무선 디버깅을 켤 때 Wi-Fi 연결과 기기에서의 네트워크 허용이 필요할 수 있습니다.

처음 준비하는 기기는 **PC 작업이 끝난 뒤 전원을 끄기 전에** 다음 절차를 한 번 진행하세요.

1. 사용할 Wi-Fi에 연결하고 무선 디버깅에서 현재 네트워크를 허용합니다.
2. Shizuku → **무선 디버깅으로 시작 / 페어링**에서 Android의 페어링 코드를 입력합니다. PC가 USB로 Shizuku를 실행한 상태여도 이 무선 페어링은 별도로 필요합니다.
3. 갤럭시 초기화 앱에서 **연결하기**를 누르고 Shizuku 권한을 허용합니다. **권한 연결됨**을 확인합니다.
4. 이후에는 같은 신뢰 Wi-Fi에서 초기화 앱을 열어 사용합니다. Android 13 이상에서 Shizuku가 재부팅 후 자동 시작을 시도합니다. 자동 시작에 실패하면 Shizuku의 **시작**을 다시 누릅니다.

기존 페어링·권한은 PC 작업과 폰 초기화 작업에서 보존합니다. 매번 다시 페어링할 필요는 없지만, 페어링 삭제·앱 데이터 삭제·새 Wi-Fi 등의 상황에서는 재승인이 필요할 수 있습니다. USB 기동 성공만으로 무선 페어링 완료를 판정하지 않습니다.

초기화 없이 설치·설정만 준비하는 명령도 제공합니다. ADB가 PATH에 있어야 하며, `--serial`을 생략하면 연결된 기기를 준비합니다. 이 명령은 계정·앱·파일 삭제 단계를 실행하지 않습니다.

```sh
python V6.py --prepare-phone-only --serial DEVICE_SERIAL
```

Windows EXE에서도 같은 옵션을 사용할 수 있습니다.

```powershell
& '.\갤럭시 초기화 V8.exe' --prepare-phone-only --serial DEVICE_SERIAL
```

### APK 동봉 및 EXE 빌드

`phone-app/`에 고정된 서명의 초기화 APK와 공식 Shizuku APK, 버전·SHA-256 목록을 보관합니다. Android 앱을 변경하면 기존 기기와 같은 서명 키로 APK를 빌드한 뒤, 저장소 루트에서 다음을 실행해 동봉 파일을 갱신하세요. APK는 Git LFS 대상입니다.

```sh
python tools/prepare_phone_bundle.py
python tools/prepare_phone_bundle.py --check
python -m unittest -v test_phone_setup
```

첫 명령은 빌드된 초기화 APK를 복사하고 해시를 고정한 공식 Shizuku APK를 내려받습니다. 이미 받은 공식 파일은 `--shizuku-apk PATH`로 지정할 수 있습니다. EXE 시작 전에도 동봉 파일의 해시를 검사하므로, 누락·손상된 번들로 삭제 작업부터 시작하지 않습니다.

Windows에서 `pip install pyinstaller` 후 `pyinstaller V6.spec`로 빌드합니다. 결과는 `dist/갤럭시 초기화 V8.exe`입니다. **Build Windows EXE** 워크플로도 동봉 파일 검사와 준비 기능 테스트 후 빌드합니다. 이 과정은 Android APK를 다른 임시 키로 재빌드하지 않습니다. macOS에서는 Windows용 EXE를 빌드하지 않습니다.

## 실행과 복구

- 사용자가 확인해야만 실행되는 포그라운드 서비스입니다. 언어·글꼴 변경, 홈 화면 이동과 최근 앱 정리 중에도 작업은 서비스에서 진행됩니다. 화면과 진행 알림은 저장된 상태를 표시합니다.
- 앱 자신과 **Shizuku 관리자·삼성 인터넷도 삭제 제외**입니다. 18단계에서 필수 앱과 자신의 설치 상태를 확인합니다. 자신이 실행 중인 APK를 다시 설치할 필요는 없습니다.
- 자산은 앱 private cache → Binder 파일 디스크립터 → shell 소유 `/data/local/tmp/galaxy-reset`로 전달합니다. shell이 앱 private 경로를 직접 읽도록 가정하지 않습니다. DEX는 읽기 전용으로 복사합니다.
- 일반 실패는 다음 단계로 넘어가되 **실패/수동 확인**으로 남깁니다. 연결 단절·프로세스 종료는 현재 단계에서 멈추며 자동으로 삭제를 재개하지 않습니다. 재시도는 다시 삭제 확인 팝업을 거칩니다.
- 임시 비활성화 전에 패키지 목록을 내부 저장소에 기록합니다. `finally`에서 재활성화하며, 연결 단절로 복구가 불가능하면 목록을 유지합니다. 다음 실행은 재활성화부터 처리합니다. 복구가 완료되지 않으면 이후 삭제 작업을 진행하지 않습니다.
- 로그에는 계정 이름이나 e-SIM 식별자를 저장하지 않습니다. 원격 명령 출력을 제한하고 출력이 잘린 목록으로 앱을 삭제하지 않습니다.
- 알림 권한을 거부하면 알림창에 진행률이 보이지 않을 수 있습니다. 서비스 실행 여부는 Android 시스템의 실행 중인 앱 화면에서도 확인할 수 있습니다.

## 범위와 검증

이 도구는 공장 초기화/보안 삭제 도구가 아닙니다. 삼성 계정을 보존하고 V6가 대상으로 삼는 앱·사용자 파일·설정을 정리합니다. Android/One UI의 shell·SELinux 정책에 따라 보호 파일, 계정, e-SIM 삭제가 거부될 수 있습니다. 완료 표시가 기기의 모든 데이터가 완전히 없어졌다는 의미는 아닙니다.

원본 요구사항: `../docs/phone-app-requirements.md`. 문서의 디자인 링크는 읽지 못해 네이티브 UI로 화면 흐름을 구현했습니다.

단위 테스트는 앱/Shizuku 보존, 잘린 목록 거부, 위젯 영역 파싱, 비활성화 복구 기록, e-SIM 수동 처리 판정, 모델·언어·계정 규칙을 확인합니다. 실제 명령은 실행하지 않습니다. APK 빌드와 단위 테스트만으로 기기별 삭제 성공을 보장할 수 없으므로 아래 항목은 직원용 테스트 기기에서 확인하세요.

- 삼성/Google 계정 및 e-SIM 있는 기기의 결과, 실패 시 수동 안내
- Wi-Fi/Shizuku 중단 후 해당 단계 재시도 및 비활성화 패키지 복구
- 홈 키/런처 초기화/최근 앱 정리 중 서비스 유지와 화면 복귀
- 사진·휴지통·메시지·연락처·클립보드 잔여물
- 선택 언어와 보조 언어, 홈/잠금 배경 및 필수 앱
- S23/S24/S25/S26의 실제 Android/One UI 버전별 동작

API 구현 근거: [Shizuku 공식 API 안내](https://github.com/RikkaApps/Shizuku-API), [공식 UserService 샘플](https://github.com/RikkaApps/Shizuku-API/tree/master/demo).

## 1.0.1 실기기 수정

S26(Android 17)에서 확인한 문제를 수정했습니다. 계정 결과 파싱은 Android 정규식의 중괄호 해석 차이를 피하도록 문자열로 처리합니다. `dumpsys appwidget`은 전체 약 70KB 대신 Widgets 영역만 shell에서 추출해 Binder 출력 제한을 넘지 않게 합니다. 내부 저장소 검증은 빈 폴더와 시스템 `.nomedia` 및 썸네일 `.database_uuid`를 제외하고 실제 잔여 파일을 확인합니다. 실제 썸네일 이미지와 사용자 파일은 계속 잔여물로 표시합니다.

삼성 인터넷이 사용자 설치 앱인 경우에도 삭제하지 않습니다. 1.0.2부터 삼성 인터넷이 없는 기기는 설치를 건너뛰며, 실패나 수동 처리 항목으로 표시하지 않습니다. 설치되어 있으면 보존하고 활성화합니다.

## 1.1.1 화면 디자인

참고 Claude 아티팩트의 연결·시작·삭제 확인·진행·완료·일부 실패 화면을 네이티브 UI에 반영했습니다. 청록색 카드와 버튼, 언어 선택 카드, 배경 미리보기를 사용합니다. 상단 **화면 보기**에서 여섯 화면을 눌러 확인할 수 있습니다. 미리보기에서는 삭제 확인·재시도·전원 끄기 버튼도 실제 명령을 실행하지 않습니다. **실제 결과로 돌아가기**로 미리보기를 종료합니다.

진행 기록의 각 단계를 누르면 작업 내용·상태·마지막 결과를 확인합니다. 아이콘은 Google Material Symbols Rounded의 공식 SVG를 Android VectorDrawable로 변환한 리소스입니다. 라이선스와 출처는 `third-party/material-symbols`에 있습니다.

**연결하기**는 실행 중인 Shizuku에 권한을 요청·연결하거나, 꺼져 있으면 Shizuku 앱을 엽니다. Shizuku를 시작하고 돌아오면 자동 연결됩니다. 이 버튼이 OS의 페어링·Wi-Fi 신뢰 승인이나 Shizuku 시작 절차를 대신하는 것은 아닙니다.

## 1.1.2 전원 끄기 후 시작 화면

앱의 전원 끄기 명령을 보내기 전에 다음 실행 화면을 메인으로 저장합니다. 이후 앱을 다시 열면 이전 완료 화면 대신 메인·언어 선택 화면이 표시됩니다. 완료·실패 화면에서 **시작 화면으로**를 눌러도 이 선택이 유지됩니다. 마지막 실행 기록은 삭제하지 않으며 메인의 **지난 초기화 결과 보기**로 다시 확인할 수 있습니다. 새 초기화를 실행하면 이번 실행 결과를 다시 표시합니다.

S26(Android 17)에서 실제 재부팅 후 Shizuku를 수동으로 열지 않고 초기화 앱만 실행해 **권한 연결됨**과 **초기화 시작 버튼 활성화**를 확인했습니다. 이때 Shizuku 서버는 앱 실행 전부터 shell(uid 2000)로 시작돼 있었고, Wi-Fi가 연결된 상태였습니다. OS 잠금 화면은 사용자가 직접 해제했습니다. 이 검증에서는 초기화 작업을 재실행하지 않았습니다.

## 1.1.3 운영 화면 정리

상단 화면 보기·디자인 미리보기 메뉴를 제거했습니다. 단계별 작업 내용과 실제 결과를 확인하는 기능은 유지합니다. 완료 화면의 하단 버튼은 **시작 화면으로(왼쪽) / 전원 끄기(오른쪽)** 가로 배열입니다. 지난 기록은 메인의 **지난 초기화 결과 보기**로 열 수 있습니다.
